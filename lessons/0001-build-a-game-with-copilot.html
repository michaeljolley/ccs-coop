Part 1: What is an LLM? (~30 minutes)

The Big Question

You're about to use GitHub Copilot to build a game. But what IS Copilot, actually? It's not magic. Copilot is a tool powered by a Large Language Model (LLM). The LLM is the AI engine that actually generates the code; Copilot wraps that engine with the ability to read your files, run commands, and work inside your terminal. So when we ask "how does Copilot come up with code?", we're really asking how an LLM works. Understanding that will make you dramatically better at using it.

An LLM is a next-word predictor

At its core, an LLM does one thing: given some text, it predicts what comes next. That's it. It's done this prediction so many times, with so much text, that it appears to "understand," but it's fundamentally a very sophisticated autocomplete.

🧠 Think about it When you text a friend and your phone suggests the next word, that's the same basic idea, just at a much smaller scale. An LLM is your phone's autocomplete trained on essentially the entire internet.

What is a "model"?

A model is one specific version of this trained system. Different models have different strengths:

  • Bigger models: slower, more capable, better at complex reasoning
  • Smaller models: faster, cheaper, good enough for straightforward tasks
  • Specialized models: trained specifically for code, or images, or conversation

GitHub Copilot uses code-specialized models. That's why it's better at writing JavaScript than writing poetry.

Key takeaways

  • An LLM predicts text; it doesn't "think" the way you do
  • It was trained on enormous amounts of human-written code and text
  • It's very good at patterns it has seen many times before
  • It can be confidently wrong about things it hasn't seen much (more on this in Week 3)
  • YOUR job is to give it good input and verify its output
💡 Why this matters for today When you write a prompt to Copilot, you're giving the LLM text to predict from. The clearer and more specific your text, the better its predictions. You're not "asking." You're steering.

What does an LLM fundamentally do?

Searches the internet for answers Predicts what text should come next Copies code from other people's projects Runs your code and fixes any errors

Why is GitHub Copilot especially good at writing code?

It was built by professional programmers It connects to a database of correct solutions Its model was trained specifically on code It executes code and learns from the results

Part 2: Build a Game (~30 minutes)

Now that you know what's behind the curtain, let's put it to work. You're going to steer the LLM to build you a playable game.

Pick your game (2 min)

Choose a classic game to build. Pick whatever sounds most fun:

  • Tic-Tac-Toe: Two players, take turns, check for a winner
  • Snake: Move around, eat food, grow longer
  • Connect 4: Drop pieces, get four in a row
  • Memory Match: Flip cards, find matching pairs
  • Something else?: Ask your instructor
⚠️ Scope check Pick a game with rules you can explain in 2-3 sentences. Simple rules = better predictions from the LLM.

Set up your project folder (2 min)

Open your terminal. You will type three short commands. First-timer? These are the only ones you need, and they mean exactly what they say:

  • mkdir makes a folder, cd moves into it, and copilot starts Copilot. The ~ is a shortcut for your home folder.
mkdir ~/Documents/my-game
cd ~/Documents/my-game

Never used a terminal before? Read the one-page Terminal Basics reference card first.

Write your first prompt (5 min)

Now talk to Copilot. Type this in your terminal to start a session:

copilot

Copilot greets you in the terminal. Now describe your game clearly and specifically:

Create a tic-tac-toe game in a single HTML file called index.html. It should:
- Display a 3x3 grid
- Let two players take turns clicking squares (X and O)
- Detect when someone wins or it's a draw
- Show a message saying who won
- Have a "Play Again" button
- Look clean and modern with CSS styling

Remember: you're steering a next-word predictor. The more specific your description, the better its predictions will be.

💡 Tip: Copilot asks before it acts The Copilot CLI will show you what it plans to do and may ask for permission before creating or editing files. Read what it's about to do, then approve it. Type / anytime to see available commands.

Run it and iterate (20 min)

  1. Copilot will create index.html directly in your folder
  2. Open it in your browser (double-click the file, or drag it into a browser window)
  3. Play it. What works? What doesn't?
  4. Back in the terminal, tell Copilot what to fix: 
    The game works, but when I click a square that's already taken, it lets me 
overwrite it. Fix that. Also make the grid bigger and add hover effects.
  5. Refresh your browser to see the changes. Repeat!
💡 Connect to the concept Notice how Copilot is great at common patterns (a tic-tac-toe grid, a game loop) but might struggle with unusual requests. That's because the LLM has seen thousands of tic-tac-toe implementations in its training data, so it's predicting based on what it's seen before.

Wrap-up (3 min)

Show a neighbor your game. Did yours turn out differently than theirs? Same LLM, different prompts, different results, and that's the power of good steering.

Between Sessions

  • Polish your game: add one more feature using Copilot
  • Try breaking it: delete some code, then ask Copilot to help fix it
  • Reflect: When did Copilot seem "smart"? When did it seem "dumb"? (Hint: it's neither; it's predicting.)
