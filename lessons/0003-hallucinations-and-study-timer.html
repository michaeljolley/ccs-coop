Part 1: Hallucinations (~30 minutes)

A confident liar?

Last week you learned that an LLM predicts text. Here's the uncomfortable truth: it will predict confidently even when it's wrong. This is called a hallucination.

Why? Because the LLM doesn't "know" things; it predicts likely text. If the most likely next words happen to be incorrect, it'll produce them with the same confidence as correct ones.

⚠️ Real example Ask Copilot to write a timer that counts down from 25 minutes. It might use setInterval(fn, 1000), which fires every 1000 milliseconds (1 second). Seems right. But intervals can drift over time, and after 25 minutes, your timer might be off by several seconds. Copilot won't mention this unless you ask.

Why hallucinations happen

  • The LLM has seen many examples of something and predicts the most common pattern, even if it doesn't apply here
  • It doesn't verify its own output; it can't "run" code in its head
  • It fills gaps with plausible-sounding text rather than saying "I don't know"
  • Rare or unusual patterns are where hallucinations are most likely

How to catch hallucinations

  1. Test everything: run the code, check edge cases
  2. Ask "why?": "Explain why you used setInterval here. Are there downsides?"
  3. Check the math: if it involves numbers, timing, or logic, verify manually
  4. Be skeptical of specifics: if it cites a library, API, or function name, check that it exists
  5. Try to break it: what happens at edge cases? (Timer at 0, negative numbers, etc.)
💡 The mindset shift Don't think of Copilot as "right or wrong." Think of it as a first draft that's often good but always needs review. Your job is editor, not audience.

Class activity: Spot the hallucination

Let's ask Copilot to do something with a known correct answer and see if it gets it right. We'll deliberately test edge cases where it's likely to slip.

Why do LLMs hallucinate?

They're trying to deceive you on purpose They predict likely text without verifying correctness The internet contains incorrect information They run out of memory and guess randomly

What's the BEST way to catch a hallucination in generated code?

Read the code carefully for typos Ask Copilot if the code is correct Compare it to code on Stack Overflow Run it and test edge cases to verify behavior

Part 2: Build a Study Timer (~30 minutes)

A study timer (Pomodoro technique) is perfect for practicing hallucination-catching: timing logic has specific, verifiable behavior. You can see if it's wrong.

What you're building

  • A countdown timer (25 min study, 5 min break)
  • Start, pause, and reset buttons
  • Saves completed sessions to localStorage (persists between page loads)
  • Shows total sessions completed today

Your prompt

Navigate to a new project folder and start a Copilot session:

mkdir ~/Documents/study-timer
cd ~/Documents/study-timer
copilot

Then describe your timer:

Create a Pomodoro study timer in a single HTML file called index.html:
- 25-minute countdown that displays minutes:seconds
- Start, Pause, and Reset buttons
- When timer hits 0:00, show an alert and switch to 5-min break
- Track completed sessions in localStorage
- Show "Sessions today: X" counter
- Clean, modern dark-theme styling

Your mission: catch the hallucinations

After Copilot generates the code, specifically test:

  1. Does it count accurately?: Set it to 10 seconds and time it with your phone
  2. Does pause actually pause?: Pause it, wait, resume. Is the time correct?
  3. Does reset work mid-countdown?
  4. Does localStorage persist?: Complete a session, refresh the page. Is the count still there?
  5. What happens if you click Start twice?: Does it speed up? (Common bug!)
🔍 Be the editor When you find something wrong, tell Copilot exactly what you found: "When I click Start twice, the timer speeds up. It should ignore the second click if already running. Fix this."

Stretch: make it yours

If time allows, add one of:

  • A sound or notification when the timer ends
  • Custom time settings (not just 25/5)
  • A visual progress ring or bar

Between Sessions

  • Use your timer to actually study this week. You built it, you might as well use it!
  • Find one more bug: try unusual interactions (rapid clicking, leaving the page open overnight) and fix what you find
  • Deploy it to GitHub Pages if you haven't already
