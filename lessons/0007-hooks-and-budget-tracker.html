Part 1: Hooks (~30 minutes)

Events and reactions

Think about how your phone works:

  • You get a text → your phone buzzes (event → reaction)
  • You arrive at school → your phone silences itself (event → reaction)
  • It's 7am → your alarm goes off (event → reaction)

This pattern, when something happens, automatically do something else, is called a hook.

What is a hook?

A hook is an automated reaction to an event. In the AI ecosystem:

  • When code is committed → automatically run tests
  • When a file is saved → automatically format it
  • When a PR is opened → automatically review it
  • When an error is detected → automatically suggest a fix
💡 Analogy A hook is like a mousetrap: you set it up once, then it triggers automatically when the right condition occurs. You don't have to sit there watching for the mouse.

Hooks vs manual action

Manual With Hook
"Remember to run tests before pushing" Tests run automatically on every push
"Manually calculate my remaining budget" Budget recalculates when you add an expense
"Check if my code has errors after editing" Errors highlighted instantly as you type

Hooks in your apps

You've actually been using hook-like patterns already without knowing it:

  • Your game: when a player clicks → update the board
  • Your timer: when time hits zero → show alert and switch mode
  • Your weather app: when user submits a city → fetch and display data

In JavaScript, addEventListener is literally setting up a hook: "when this event happens, run this code."

Hooks in the Copilot ecosystem

GitHub Copilot can use hooks to automate your development workflow:

  • Pre-commit hooks: Check code quality before you commit
  • On-save hooks: Format code every time you save a file
  • CI/CD hooks: Deploy your site automatically when you push to GitHub

A "hook" in programming is best described as:

An automated reaction triggered by a specific event A way to connect two different programming languages A security measure that blocks unauthorized access A visual element that grabs the user's attention

Part 2: Build a Budget Tracker (~30 minutes)

Your most data-rich app yet. It combines everything you've learned: events, localStorage, rendering data, and now, charts.

What you're building

  • Add income and expenses with a category (food, transport, entertainment, etc.)
  • Running balance that updates automatically (a hook!) when you add a transaction
  • Simple bar or pie chart showing spending by category
  • All data saved to localStorage
  • Ability to delete entries

Your prompt

New project, new folder:

mkdir ~/Documents/budget-tracker
cd ~/Documents/budget-tracker
copilot

Describe your tracker:

Create a budget/expense tracker in a single HTML file called index.html:
- Input form: amount, description, category (dropdown: Food, Transport, 
  Entertainment, School, Other), and type (income/expense)
- Transaction list showing all entries with delete buttons
- Running balance at the top that recalculates automatically 
  when entries are added or removed
- A simple bar chart showing total spending per category 
  (use canvas or inline SVG, no external libraries)
- All data persisted in localStorage
- Clean, modern styling with green for income, red for expenses

Notice the hooks

As you build, identify the hooks (event → reaction) in your tracker:

  • When "Add" is clicked → add to list, recalculate balance, update chart
  • When "Delete" is clicked → remove from list, recalculate balance, update chart
  • When page loads → load from localStorage, render everything
🔍 Test the chain Add an expense → does the balance update? Does the chart update? Delete it → does everything revert? If not, you've found a bug in your hook chain. Tell Copilot exactly which reaction didn't fire.
