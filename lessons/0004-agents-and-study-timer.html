Part 1: What Are Agents? (~30 minutes)

Chat vs Agent

So far, you've been using Copilot as a chat: you ask, it answers, you apply the code manually. That's like texting a friend for advice and doing the work yourself.

An agent is different. An agent can:

  • Take actions: edit files, run commands, create new files
  • Make decisions: decide what step to take next without asking you
  • Use tools: run your code, read error messages, search the web
  • Loop: try something, check if it worked, try again if not
💡 Analogy Chat = you ask a chef for a recipe, then cook it yourself.
Agent = you tell the chef what you want for dinner, and they go make it, choosing ingredients, adjusting seasoning, plating it.

The Agent Loop

An agent works in a loop:

  1. Observe: read files, see errors, understand the current state
  2. Think: decide what action to take next
  3. Act: edit a file, run a command, create something
  4. Check: did it work? If not, go back to step 1

This is exactly what YOU have been doing manually: observe the bug, think about the fix, make the edit, test it. An agent automates this loop.

Agents in Copilot

Here's the surprise: the Copilot CLI is an agent. Every time you've described what you want and watched it create files, run commands, and deploy your apps. That was the agent loop in action. Instead of just chatting, it directly edits your files, runs terminal commands, and iterates on its own work. You're the supervisor, not the typist.

Asking vs tasking

Even with one tool, you interact in two different ways. Sometimes you ask (like a chat) and sometimes you task (like an agent):

You're asking when... You're tasking when...
You want to understand something You want something built or fixed
"Explain what localStorage does" "Add a stats dashboard to my timer"
You want a single answer, no file changes The task involves editing files and multiple steps

The Copilot CLI handles both. The difference is in how you phrase your request.

⚠️ Agents still hallucinate An agent is just an LLM in a loop. It can still be confidently wrong; it just does it faster and across more files. Always review what an agent does before accepting.

What makes the Copilot CLI an agent rather than just a chatbot?

It is smarter and never makes mistakes It answers questions but cannot edit any files It can take actions and iterate on its own work There is no real difference, just different names

Part 2: Extend Your Study Timer (~30 minutes)

Today you'll task the Copilot CLI to add features to your study timer, giving it a goal and letting it make the edits while you supervise.

Be intentional about tasking

Good news: you've been working with an agent this whole time. The Copilot CLI is inherently agentic. It reads your files, edits them directly, and can run commands. When you've been typing descriptions and watching it create index.html, that's agent behavior.

Today, let's be more intentional about it. Navigate to your study timer project:

cd ~/Documents/study-timer
copilot

Give the agent a task

Instead of describing code changes, give it a goal:

Add a statistics dashboard to my study timer. It should:
- Show a bar chart of sessions completed each day this week
- Display total focus minutes this week
- Show current streak (consecutive days with at least 1 session)
- Store all data in localStorage
- Add it below the timer in the same page

Your role: supervisor

Watch what Copilot does. It will:

  • Read your existing index.html to understand the structure
  • Make edits directly to the file
  • Possibly create additional files if needed

After it's done:

  1. Open index.html in your browser. Does it look right?
  2. Test the stats. Do numbers add up?
  3. If something's off, tell Copilot: "The bar chart isn't showing today's sessions. Fix it."
🔍 Compare the experience Now that you know you've been working with an agent all along, think about the loop: you describe a goal → the agent observes your files → it makes edits → you check the result → you give feedback. That's the agent loop from Part 1!

Deploy your update

Ask Copilot to deploy it for you:

Deploy this to GitHub Pages. Create a public repo called study-timer, 
push the code, enable Pages, and give me the URL.

Between Sessions

  • Task the CLI to add one more feature to any of your projects
  • Compare: Try asking a question ("explain how my timer works") vs giving a task ("add a pause sound"). Notice how the CLI responds differently.
  • Reflect: When did you feel comfortable letting the agent work? When did you want more control?
