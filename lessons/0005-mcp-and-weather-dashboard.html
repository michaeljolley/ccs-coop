Part 1: MCP, the Model Context Protocol (~30 minutes)

The problem MCP solves

So far, Copilot has only known what's in your files and your chat messages. But what if it needs to:

  • Look up today's weather?
  • Check your calendar?
  • Query a database?
  • Read documentation from the web?

An LLM by itself can't do any of these. It's a text predictor trapped in a box. MCP is the door out of that box.

What is MCP?

Model Context Protocol is a standard way to connect AI models to external tools and data sources. Think of it as a universal adapter:

  • The AI says: "I need weather data for Chicago"
  • MCP routes that request to a weather tool
  • The tool fetches real data and sends it back
  • The AI uses that data in its response
💡 Analogy You know how your phone can connect to Bluetooth speakers, car systems, headphones, all different devices, one standard protocol? MCP is Bluetooth for AI tools. One standard way to plug in any data source.

MCP in the ecosystem

Without MCP With MCP
AI only knows what's in its training data AI can access live, real-time information
Every tool needs custom integration One standard protocol for all tools
AI hallucinates facts it doesn't have AI can look up facts before responding

How this connects to what you're building

Today you'll build a weather app that fetches real data from an API. This is the same fundamental pattern MCP uses. Your code reaches outside itself to get live information. The difference is:

  • Your app calls an API using JavaScript (fetch())
  • An MCP tool does the same thing, but on behalf of the AI

Same concept, different user. Today you're the one calling the API. With MCP, the AI makes that call for you.

What problem does MCP solve?

Makes LLMs generate code faster Connects AI to external tools and live data Prevents hallucinations from ever occurring Replaces the need for programming languages

MCP is best compared to:

A programming language that AI uses internally A firewall that protects AI from bad data A universal adapter connecting AI to any tool A search engine built into every LLM
💡 You're already using MCP! Remember how you deployed by just asking Copilot to "create a repo and enable Pages"? The Copilot CLI did that using its built-in GitHub MCP server, an MCP tool that connects it to GitHub. When you asked, Copilot used that tool to create your repository. That's MCP working for you right now, in the tool you use every class.

Part 2: Build a Weather Dashboard (~30 minutes)

Your first app that reaches outside itself for data. You'll use a free weather API, no signup or credit card needed.

The API

We'll use Open-Meteo, a free, no-key-required weather API. It returns real weather data in JSON format.

Your prompt

Set up a new project and start a Copilot session:

mkdir ~/Documents/weather-app
cd ~/Documents/weather-app
copilot

Then describe your dashboard:

Create a weather dashboard in a single HTML file called index.html using 
the Open-Meteo API (https://api.open-meteo.com/v1/forecast). It should:
- Have a search box where I type a city name
- Use the Open-Meteo geocoding API to find the city's coordinates
- Fetch current weather (temperature, wind speed, weather condition)
- Show a 5-day forecast with high/low temps
- Display weather icons or emoji based on conditions
- Handle errors gracefully (city not found, network issues)
- Modern, clean styling with a blue gradient header

What's new here

This app introduces asynchronous code: your app sends a request, waits for a response, then displays it. This is the fetch() → await → render pattern you'll see everywhere in web development.

⚠️ Hallucination alert Copilot might hallucinate API endpoints or parameters that don't exist. If the weather data isn't loading, check the Open-Meteo documentation to verify the actual API format. This is a real skill: verifying that generated API calls match reality.

Test it

  1. Search for your city. Does it show weather?
  2. Search for a city that doesn't exist. Does it show an error gracefully?
  3. Is the temperature in the right unit (°F or °C)?
  4. Does the 5-day forecast look reasonable for your area?

Stretch goals

  • Remember the last searched city (localStorage)
  • Add a "Use my location" button (geolocation API)
  • Show a loading spinner while fetching

Between Sessions

  • Deploy it: push to GitHub Pages
  • Try a different API: Ask Copilot to help you swap to a different free API (like a quotes API or Pokémon API). Notice how the fetch pattern is the same even with different data.
  • Think about MCP: Imagine if Copilot could call the weather API FOR you while chatting. That's MCP in action.
